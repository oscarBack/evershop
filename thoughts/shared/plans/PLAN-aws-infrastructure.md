# Plan: AWS Infrastructure for EverShop

## Goal
Build production-ready, highly available AWS infrastructure for the EverShop Next.js/Node.js eCommerce application using Terraform, following best practices for security, maintainability, and scalability.

## Technical Choices
- **Compute**: Amazon ECS with AWS Fargate - Serverless container execution, ideal for Dockerized web apps (based on provided `Dockerfile` and `docker-compose.yml`), low maintenance overhead.
- **Database**: Amazon RDS for PostgreSQL - Managed relational database mapping to local `postgres:16` container, provides automated backups, high availability, and easy scaling.
- **Networking**: VPC with Public and Private Subnets - Strict network isolation. ALBs in public subnets routing to ECS tasks in private subnets. RDS in isolated private database subnets.
- **Storage**: Amazon S3 - For storing uploaded media/static assets generated by EverShop (requires environment configuration).
- **Infastructure as Code Framework**: Terraform - Using official AWS modules where applicable, remote state in S3 with native S3 state locking (`use_lockfile = true`), and 2 Terraform Workspaces (`stage` and `production`) for managing multi-environment infrastructure securely. Note: DynamoDB-based locking is deprecated per HashiCorp docs.
- **Secrets Management**: AWS Secrets Manager - Strict requirement for all sensitive credentials (database passwords, API keys, etc.). Credentials will be dynamically fetched at runtime by ECS and are never to be stored in plain text or passed unsafely.

## Current State Analysis
EverShop is currently structured to run via Docker Compose with two main services:
- `app`: Node.js/React application exposing port 3000.
- `database`: PostgreSQL 16 database.

### Key Files:
- `Dockerfile` - Used to build the application container.
- `docker-compose.yml` - Reference for environment variables (`DB_HOST`, `DB_PORT`, `DB_PASSWORD`, `DB_USER`, `DB_NAME`).

## Tasks

### Task 1: Terraform Repository & Backend Setup
Set up the foundational Terraform structure, remote state backing, and provider configurations using Terraform Workspaces.
- [ ] Initialize Terraform root with `backend.tf` config for S3 remote state and enable native S3 state locking (`use_lockfile = true`), as DynamoDB locking is now deprecated.
- [ ] Create `terraform workspace new stage` and `terraform workspace new production`.
- [ ] Create `terraform/environments/` containing `stage.tfvars` and `production.tfvars`. Use these based on the active workspace.
- [ ] Configure `provider.tf` pinning AWS provider versions `~> 5.0`.

**Files to modify:**
- `terraform/backend.tf`
- `terraform/provider.tf`
- `terraform/variables.tf`

### Task 2: Networking Module (VPC)
Provision a secure, highly available network layout.
- [ ] Use `terraform-aws-modules/vpc/aws` to create a VPC across 2+ Availability Zones.
- [ ] Create public subnets (for NAT Gateway and ALB).
- [ ] Create private subnets (for ECS tasks).
- [ ] Create isolated database subnets (for RDS).

**Files to modify:**
- `terraform/modules/networking/main.tf`
- `terraform/modules/networking/outputs.tf`

### Task 3: Database Storage (RDS PostgreSQL)
Provision a managed PostgreSQL database replacing the local container.
- [ ] Create AWS RDS PostgreSQL 16 instance using `terraform-aws-modules/rds/aws`.
- [ ] Configure automated backups, Multi-AZ deployments (for `production` workspace only, keeping `stage` single-AZ), and encryption at rest.
- [ ] Set up DB Security Groups allowing ingress only from ECS tasks.
- [ ] Generate DB credentials (e.g. `DB_PASSWORD`) via `random_password` inside Terraform and immediately store them in AWS Secrets Manager.
- [ ] Output the Secrets Manager ARN for ECS tasks to assume via IAM policies.

**Files to modify:**
- `terraform/modules/database/main.tf`

### Task 4: Application Load Balancer Setup
Route user traffic to application containers.
- [ ] Create an Application Load Balancer in the public subnets.
- [ ] Set up HTTP/HTTPS listeners and target groups.
- [ ] Setup Security Group allowing ports 80/443 from anywhere.

**Files to modify:**
- `terraform/modules/alb/main.tf`

### Task 5: Compute (ECS Fargate)
Run the application container securely.
- [ ] Create ECS Cluster.
- [ ] Create ECS Task Definition referencing the Docker image (stored in ECR).
- [ ] Configure environment variables in the task definition (injecting `DB_PASSWORD`, `DB_USER` straight from AWS Secrets Manager using the `secrets` container definition block). Map non-sensitive vars (`DB_HOST`, `DB_PORT`, `DB_NAME`) normally.
- [ ] Attach an Execution IAM Role that strictly allows `secretsmanager:GetSecretValue` on the deployed database credentials.
- [ ] Create ECS Service with autoscaling policies attached to the ALB Target Group.
- [ ] Setup ECS Security Groups allowing ingress only from the ALB on port 3000.

**Files to modify:**
- `terraform/modules/ecs/main.tf`

### Task 6: ECR and CI/CD Pipeline Configuration
Ensure automated deployments can update the application.

- [ ] Create IAM Roles/Policies for GitHub Actions / CI/CD pipeline to push to ECR and deploy to ECS.

## Success Criteria

- [ ] Run `terraform fmt -check -recursive` successfully.
- [ ] Run `terraform validate` successfully in environment roots.
- [ ] Run `tflint` across all modules without errors.

### Manual Verification:
- [ ] Perform `terraform plan` to ensure execution dry-run succeeds without errors.
- [ ] Manually verify ALB URL serves the EverShop application.
- [ ] Confirm ECS tasks can connect to the RDS instance and database tables initialize.
- [ ] Verify native S3 backend state locking operates correctly.

## Out of Scope
- Initial continuous deployment (CI/CD) YAML workflows (e.g. GitHub Actions), as this focuses purely on the AWS infrastructure setup.
- Domain name registration or Route53 hosted zone creation (assumed existing or handled externally).
- Application code modifications to support additional AWS services beyond standard DB variables.

## Risks (Pre-Mortem)

### Tigers:
- **Database Migrations on Startup** (MEDIUM)
  - Issue: If multiple ECS tasks start simultaneously during a deployment, they might try to execute database schemas at the same time causing race conditions.
  - Mitigation: Use a standard init/migration one-off task in the pipeline before rolling out the new service deployment, or ensure the app handles idempotent migrations cleanly.

### Elephants:
- **State File Security** (LOW)
  - Issue: Backend tfstate might contain sensitive infrastructure tokens.
  - Note: Mitigation included via S3 SSE encryption, bucket versioning for safety, and native S3 state locking via `use_lockfile`.
